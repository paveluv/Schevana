# Platforms

Schevana runs on a stack of layers that differ from machine to machine: the
OS, the windowing protocol (Wayland, X11, the Mac's), the compositor, SDL's
version, the GPU API (Vulkan, Metal), the driver, the monitor. A feature that
works on one stack may do nothing, or something wrong, on another. This file
records what has run where, and where each platform-specific feature is
expected to work.

Code that differs by platform belongs in the platform files:
`schevana/core0/platform.sls` for core0's,
`schevana/core/platform.sls` for the core's (the rule is in
`AGENTS.md`). Which platform this is comes only from the platform
predicates and facts (`platform-mac?`, `platform-wayland?`,
`platform-vulkan?`, ...), which Monitor's Platform tab lists. A feature
made on one platform is off on the others until someone makes it work
there; off means "not there", never a crash.

## How to add to it

When you run Schevana on a platform, add a row to "Runs" with what you ran
and what happened, at the commit you ran. Monitor's Platform tab has a
button, "Copy as a row", that puts this run's row on the clipboard with
everything filled in but the result, and "a real window" as what ran. When
you add or change a feature that differs by platform, add or change its
row in "Features": where it was tested, where it should work too and why,
and what happens without it. Take versions from the machine
(`scheme --version`, the package manager, `vulkaninfo --summary`, the
compositor's `--version`), not from memory; write "not recorded" when you
don't know.
